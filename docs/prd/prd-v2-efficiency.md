| 项 | 内容 |

| 本期定位 | 在 V1 可用基础上，解决“催办、筛选、导出、核对效率”问题 |


## 1. 版本目标

V1 解决了“能不能用”的问题，V2 解决“用起来是否省时间”的问题。本期重点不是新增业务类型，而是提升管理员在月度管理中的效率，让系统从单纯台账工具升级为真正的“月度管理驾驶舱”。

V2 核心目标：

1. 管理员一眼看到月度填报进度。
2. 管理员快速定位未填报员工和异常名单。
3. 管理员可以按条件筛选借支与考勤数据。
4. 管理员可导出员工、考勤、借支三类 Excel。
5. 员工核对链路更顺畅，月度公示更易传播。

## 2. 背景与升级原因

V1 上线后，团队已经能完成数字化记录，但仍有以下问题：

1. 月底催考勤仍然依赖人工翻列表，效率不高。
2. 记录量增多后，借支和考勤查询开始变慢、难找。
3. 线下仍然需要导出表格给财务或老板核对。
4. 项目完工后仍混在有效项目里，影响员工填报体验。
5. 员工需要被动等待核对结果，缺少标准化公示路径。

## 3. 本期用户与核心价值

| 用户 | 本期新增价值 |
| --- | --- |
| 管理员 | 更快找到未填报员工、快速导出、项目状态可维护 |
| 员工 | 月度公示更透明，查询路径更短 |
| 财务/老板 | 可直接接收标准化 Excel，不再重复人工整理 |

## 4. 版本范围

### 4.1 本期新增/强化模块

1. 管理员首页月度进度看板。
2. 未填报名单与完成率展示。
3. 员工列表搜索、绑定状态筛选、导出员工表。
4. 考勤明细按月/按工人/按项目筛选与导出。
5. 借支明细按月/按工人筛选与导出。
6. 项目状态管理，支持完工下线。
7. 公示页支持按月分享。

### 4.2 不在本期范围

1. 实时工资结算。
2. 自动薪资单。
3. 多管理员协同审批。
4. 企业微信、ERP、银行代发对接。

## 5. 用户场景

### 5.1 管理员催办场景

1. 管理员打开首页。
2. 选择目标月份。
3. 查看应填报人数、已填报人数、未填报人数、完成率。
4. 进入未填报名单，逐个催办。

### 5.2 月底导出场景

1. 管理员进入员工管理、考勤明细或借支明细。
2. 设置筛选条件或导出月份范围。
3. 生成并下载 Excel。
4. 将文件转发给老板、财务或员工群。

### 5.3 项目生命周期管理场景

1. 管理员在项目管理页新增项目。
2. 项目结束后标记“已完工”。
3. 完工项目不再出现在员工可填报项目列表中。

## 6. 核心指标

1. 月底从打开系统到定位未填报名单的耗时小于 1 分钟。
2. Excel 导出成功率大于 95%。
3. 完工项目从可填报池中移除，员工误选率显著下降。
4. 管理员对“本月谁没交”的口头确认次数下降 50% 以上。

## 7. 信息架构变化

### 7.1 首页升级

首页从“简单入口页”升级为“月度管理看板”：

1. 月份切换器
2. 应填报/已填报/未填报统计
3. 完成率进度条
4. 未填报名单
5. 公示报表入口
6. 催办入口

### 7.2 管理中心升级

管理中心保留 4 个入口，但每个入口均新增“搜索/筛选/导出”能力：

1. 员工管理
2. 工地项目管理
3. 考勤明细管理
4. 借支管理

## 9. 业务规则

1. 首页统计口径以 `workers` 总人数与 `attendance` 去重工人数为准。
2. 考勤导出按 `attendance.entries[]` 展平为行。
3. 借支导出按日期范围查询。
4. 导出文件需限制最大行数，避免生成失败。
5. 已完工项目不参与员工可填报项目查询。

## 10. 数据与技术设计

### 10.1 重点集合

| 集合 | 本期用途 |
| --- | --- |
| `workers` | 绑定状态、导出员工信息、未填报名单 |
| `projects` | 项目状态控制、项目筛选 |
| `attendance` | 月度统计、明细聚合、报表导出 |
| `advances` | 借支明细查询与导出 |

### 10.2 核心云函数

| 云函数 | 作用 |
| --- | --- |
| `getAttendanceSummary` | 统计月度应填报/已填报/未填报 |
| `getWorkers` | 管理员查询员工列表 |
| `exportWorkers` | 导出员工表 |
| `exportAttendance` | 导出考勤明细 |
| `exportAdvance` | 导出借支明细 |
| `getProjects` | 获取可填报项目 |

## 11. 非功能需求

1. 单次列表查询应控制在微信云数据库限制内，必要时分页。
2. 导出文件名应包含月份范围和生成时间。
3. 导出完成后应直接打开文档，并保留微信分享菜单。
4. 无数据时页面必须提供空状态，不出现白屏。

## 12. 开放问题

1. 催办是否只做前端反馈，还是必须接入真正的微信通知。
2. 员工导出是否要脱敏手机号。
3. 大于 1000 人、跨多个月份导出时是否需要异步任务机制。

## 13. 里程碑计划

| 阶段 | 交付内容 |
| --- | --- |
| M1 | 首页看板与月度统计 |
| M2 | 员工管理搜索筛选与导出 |
| M3 | 考勤/借支明细筛选与导出 |
| M4 | 项目完工管理、公示分享、灰度上线 |

## 14. 风险与应对

1. 云数据库分页与导出量限制可能影响大团队使用。
2. 旧数据字段可能存在 `worker_id/workerId`、`worker_name/workerName` 并存，需要兼容。
3. 催办如果只做前端提示，真实触达效果有限，需要后续接入订阅消息。
4. 项目权限若配置成“仅创建者可写”，会导致现场无法正常维护。

## 15. 验收标准

1. 管理员可按月查看完整进度数据。
2. 员工、考勤、借支三类数据均可成功导出 Excel。
3. 项目标记完工后不再出现在员工填报页。
4. 管理员可在 3 次点击内定位某员工的当月考勤与借支情况。
